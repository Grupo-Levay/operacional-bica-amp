## Notes

### Ordem de Implementação
1. **Dashboard** (primeira — maior impacto visual)
2. **Reservas** (segunda — crítica operacional)
3. **Escala** (terceira — complexa, bom para testar drag-drop)
4. **Fichas** (quarta — simples, boa para validar padrão)
5. **Estoque** (quinta — consolida aprendizados)
6. **Aplicar tokens globalmente** (sexta — cleanup final)
7. **Validação visual + performance** (sétima — verificação)

### Design Decisions
- **Bento grid**: 4 cols desktop, 2 tablet, 1 mobile (CSS Grid com auto-fit)
- **Cards**: shadow-lg + glow-brand-sm on hover, rounded-xl, p-5
- **Typography**: Use h1-h3 para headings, body para conteúdo, label para UI text
- **Colors**: primary/secondary para brand, success/warning/danger para status
- **Touch targets**: SEMPRE 52px mínimo (WCAG 2.5.5)

### Risk Mitigation
- **Risk**: Mudança visual quebra funcionalidade
  - **Mitigation**: Testes E2E rodando em cada página
- **Risk**: Performance degrada
  - **Mitigation**: Lighthouse checks em cada página, lazy-loading de imagens
- **Risk**: Acessibilidade regressão
  - **Mitigation**: WCAG 2.1 AAA checklist antes de merge
