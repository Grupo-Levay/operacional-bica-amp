# S4.1 — Reservas: Operação em Tempo Real

**Estado:** done
**Modo:** Deep
**Agente:** dev

## Description
Upgrade funcional do módulo de Reservas com foco na operação real de uma noite de
bar. Hoje o fluxo cobre o cadastro (`pendente → confirmada → concluída`), mas deixa
buracos operacionais: escolha de mesa "às cegas", ausência de controle de
comparecimento (check-in / no-show) e impossibilidade de editar uma reserva.

## Acceptance Criteria
- **AC1 — Disponibilidade de mesas:** ao informar horário no formulário, o seletor
  de mesa indica quais estão livres/ocupadas no período, evitando o erro de colisão
  só descoberto ao salvar.
- **AC2 — Best-fit:** entre as mesas livres que comportam o nº de pessoas, o
  formulário sugere a de capacidade mais justa (sem queimar mesa grande com poucos).
- **AC3 — Check-in / No-show:** novos estados `presente` (cliente chegou) e
  `nao_compareceu` (não veio), com máquina de transições validada no servidor.
- **AC4 — Editar reserva:** alterar nome, telefone, horário, mesa, pessoas e obs de
  uma reserva existente, com revalidação de capacidade e colisão (excluindo a própria).
- **AC5 — Qualidade:** lint + typecheck + testes passam; transições e edição cobertas
  por testes vitest.
